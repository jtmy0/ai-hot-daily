揭秘Anthropic的「暴利」真相：缓存税-36氪

这两天，AI 开发者圈被一条透着魔幻的帖子炸翻了。

发帖的是 Java 界响当当的传奇人物、Java Champion 得主 Vlad Mihalcea。

他盯着自己过去一年的 Claude 账单，直接发出了灵魂拷问：「我彻底看不懂 Anthropic 的商业模式了。我的 Pro 套餐一年才花 200 美元，结果我生生用掉了 160 亿个 Token——要是按 API 按量计费，这笔账得高达 10 万美元！」

10 万美元的东西，200 美元卖给你？这哪是科技公司，这分明是硅谷活菩萨在拿投资人的钱撒币做慈善啊。

如果你觉得这只是某个「肝帝」程序员的极端个案，那最近刚出炉的一份实测数据只会让你更怀疑人生。

就在 2026 年 11 月 20 日，有硬核玩家通过真实使用数据反推了三大 AI 订阅的每周等效额度：

每月 20 美元的 Claude Pro 套餐（跑 Opus 5.5 + Claude Code），每周能啃下约 8.18 亿 Token；要是升级到 200 美元/月的 Claude Ultra 或 ChatGPT Pro，每周的 Token 消耗量直接飙到 81.8 亿和 93.85 亿，连相对克制的 Google AI Ultra 20X 也能给到 51.64 亿。

半导体分析机构 SemiAnalysis 甚至算过一笔总账：花 200 美元/月买 Claude 顶级订阅，最高能薅出价值 8000 美元/月的等效 API 用量，而 OpenAI 这边更是高达 14000 美元/月——账面上看，厂商贴了整整 40 到 70 倍的血本。

看到这儿，不少吃瓜群众已经开始替 Anthropic 捏把汗了：这生意还怎么做？怕不是明天就要算力崩盘、原地退市？

就在大家议论纷纷时，知名技术通讯《The Pragmatic Engineer》创始人 Gergely Orosz 出来解惑了：

「所有软件工程师都必须搞懂一件事：推理工程的第一课就是——读 KV 缓存便宜到近乎免费，推测解码又让长会话效率暴涨。而编程场景偏偏把这两项技术用到了极致。这就是为什么 AI 推理其实超级赚钱！」

好家伙，原来我们以为自己在疯狂「薅羊毛」，其实人家在后台数钱数到手抽筋。

这笔账到底是怎么算过来的？今天咱们就把 Anthropic 商业模式背后的赚钱逻辑扒个底朝天。

160亿Token的幻觉，Coding Agent是个「重度复读机」

要破案，咱们得先搞清楚一个问题：Vlad 烧掉的那 160 亿个 Token，真的都是 Claude 绞尽脑汁、一个字一个字敲出来的「原创内容」吗？

绝对不是。

在早期的聊天机器人时代，你问一句、AI 答一句，Token 消耗是线性增长的。但现在是Coding Agent（编程智能体）的时代，整个游戏规则全变了。

一个编程智能体干活，本质上是一个疯狂死循环的「复读机」：

它先通读你整个代码库的上下文（假设有 N 个 Token），想了一秒钟，决定调用一个工具去搜文件；工具返回了几行结果，它把新结果拼在后面，再把之前所有的上下文从头到尾重新读一遍；接着调用下一个工具跑单元测试，返回报错，再从头重读一遍。

如果一次任务调用了 T 次工具，模型总计要读取的输入 Token 数量就会飙升到 N×T 的量级。会话越长、工具调得越勤，总 Token 数就呈平方级爆炸。

很多开发者一直以为，账单里最贵的是单价高昂的「输出 Token」（Output Tokens）。

Typesafe 联合创始人兼 CEO Diogo Almieda 专门写了个模拟器，用 Fable 5 的定价重放了英伟达 Open-SWE-Traces 的真实编程轨迹，结果发现：真正用来生成代码和回复的输出 Token，只占总账单的 9% 到 18%！

另一位开发者 Martin Alderson 模拟了一个 6 万 Token 上下文、100 轮对话的 Opus 5 会话，结果显示约 76% 的账单全花在了「缓存读取（Cache Reads）」上。

换句话说，在真实的编程 Agent 场景里，超过 90% 的 Token 消耗，其实都是模型在反复读取自己几秒钟前刚看过的历史记录。

说到这儿你可能会问：就算它是在反复「重读」，那也是读了 160 亿个 Token 啊，GPU 不费电吗？凭什么这就能让 Anthropic 赚得盆满钵满？

这就得请出第一张真正的底牌了。

底牌一：KV缓存，AI厂商的「零边际成本印钞机」

别被「KV 缓存（KV Cache）」这种词吓住，理解大模型推理的物理成本，其实只需要记住三件事：

第一步：预填充（Prefill）——费算力。当模型第一次读你的代码库时，GPU 必须开足马力做大量矩阵运算，把这些文字转化成机器能理解的中间状态（激活值），然后顺手存进显存里。这存下来的「读书笔记」，就是KV 缓存。一旦写完缓存，下次再读同样的内容时，完全不需要重新计算。

第二步：解码（Decode）——费显存带宽。模型开始往外吐字（生成输出 Token）时，每吐出一个字，都得把整个 KV 缓存从高带宽显存（HBM）里搬运出来看一遍。这一步计算量很小，但数据搬运量巨大。这也是为什么各家 API 的输出 Token 单价往往比输入贵 5 倍——解码阶段的显存带宽，才是大模型推理真正的物理瓶颈。

第三步：工具调用——只是按了个「暂停键」。当 Coding Agent 停下来去跑个 grep 或者执行一段脚本时，之前算好的整个 KV 缓存其实就安安静静地躺在内存里。让一堆字节在内存里躺几秒钟，既不消耗算力，也不占用显存带宽。

现在，最荒诞、也最暴利的一幕出现了。

当模型一口气生成输出时，它每生成一个字都要把整个 KV 缓存读一遍，厂商并不额外收你「读缓存费」，因为这笔开销早就打包算在昂贵的输出单价里了。

可一旦 Agent 停下来调了个工具再继续，API 立刻板起脸，对着躺在内存里纹丝未动、几乎零计算成本的同一份 KV 缓存，再按 Token 数量收你一笔「缓存读取费」。

Diogo Almieda 把这事总结得极为辛辣：你之所以在工具调用后还要为 KV 缓存买单，没有什么深奥的技术苦衷，纯粹就是因为——「厂商就这么定价，你爱用不用。」

Anthropic 自己早就无意间把底细漏出来了。

如果你去翻 Claude API 的文档，会发现一个极其耐人寻味的细节：缓存读取的 Token，根本不计入 API 的输入速率限制（Rate Limits）！

你想想，速率限制是干嘛用的？是用来保护服务器别被流量打爆的。

Anthropic 敢把缓存读取排除在限流之外，等于拿大喇叭对着全世界喊：「这玩意儿压根不占我多少真实算力，你们随便读！」

至于 OpenAI，早年更是免费跑了一年多的自动前缀缓存，直到推出 GPT-5.6 才学着 Anthropic 给缓存写入加上了 1.25 倍的溢价。

把这层窗户纸捅破，Vlad 那 10 万美元的悬案就瞬间水落石出了。

那 10 万美元，并不是 Anthropic 的真实成本，而是建立在「对几乎免费的缓存读取层层加价」之上的 API 价目表算出来的。

对按量付费的企业客户，编程 Agent 每多调一次工具，厂商就多收一笔「缓存税」。这笔钱几乎不花成本，推理利润率自然越报越高。

而对每月付 20 美元或 200 美元的订阅用户，Anthropic 把这笔「缓存税」免了，让你放开了烧几十亿、上百亿 Token。账面上看像是倒贴了几十倍，实际上厂商真正花出去的硬件成本，很可能只是标价的一个零头。

不过零头也是钱。SemiAnalysis 10 月估算，订阅只贡献 Anthropic 约一成营收，却吃掉四成以上的推理算力，把套餐用到顶的重度用户，多半还是要它倒贴。

底牌二：推测解码——把GPU的「摸鱼时间」榨干

如果说 KV 缓存把「读输入」的成本打到了地板上，那刚才提到的真正物理瓶颈——「吐输出」的解码阶段，Anthropic 又是怎么省钱提速的？

这就轮到 Gergely Orosz 点出的第二张底牌登场了：推测解码（Speculative Decoding）。

前面说过，模型在解码吐字时，主要卡在显存带宽上，导致 GPU 内部极其昂贵的算力核心大部分时间其实处于「闲置摸鱼」的状态。就像一位米其林大厨站在灶台前，90% 的时间都在干等配菜员端菜上来。

推测解码干的事，就是把大厨的摸鱼时间彻底榨干。

厂商会在大模型旁边配一个极快的小模型（或者专门的预测器）当「速记员」，让它先一口气盲猜出接下来的好几个 Token，然后打包塞给大模型，让大模型利用闲置算力，一次前向计算就同时验证这好几个字猜得对不对。猜对了直接全部放行，猜错了再打回去重写。

你猜哪种场景，最适合「盲猜」？写诗不行，因为诗人下一句可能天马行空；但写代码简直是天作之合！

代码充满了高度可预测的结构：固定的语法括号、重复出现的变量名、照搬上下文里的函数签名、对现有代码做微小的重构修改……小模型猜代码，一猜一个准，接受率高得吓人。

结果就是，原本需要搬运五六次显存才能吐出来的代码，现在搬运一次就全搞定了。

现在把两张底牌合在一起看，一幅完美到令人拍案叫绝的商业拼图就出来了：

输入端靠 KV 缓存：Agent 疯狂重读上下文？几乎零算力成本，API 照收缓存费，订阅制轻松给超高额度；

输出端靠推测解码：代码高度可预测，用闲置算力把生成速度和吞吐量拉满，进一步压低单次会话的真实成本。

哪怕如今大模型越来越商品化、开源模型步步紧逼，前沿实验室的推理毛利率反而越做越高，秘密就藏在这里。

看透底牌后，谁在赢，谁在交学费？

拆解完这套「推理经济学」，我们再回过头看眼下的 AI 江湖，很多看似矛盾的现象瞬间就变得通透起来，而不同角色的应对策略，其实已经泾渭分明。

首先，如果你是普通个人开发者，别纠结了，继续安心「薅」订阅套餐就是最划算的买卖。

无论是 200 美元一年的 Pro，还是 200 美元一个月的顶级档，厂商用极低的边际成本换你的长期留存和生态粘性，这是一场罕见的双赢。下次再看到后台动辄几十亿的 Token 统计，大可会心一笑。

如果你是正在做 AI Agent 的技术团队，千万别踩「智能路由（Smart Routing）」的坑！

很多团队为了省钱，喜欢在 Agent 里加个路由器：难题发给 Opus，简单步骤切给便宜的 Sonnet。听着很聪明？其实亏到姥姥家了。

因为KV 缓存无法在不同模型之间共享！

实测算过一笔账：在一个 10 万 Token 上下文的 Opus 5 会话里，哪怕下一步只需要生成 1000 个 Token，只要你中途切给便宜模型，就得被迫把 10 万上下文从头重新写入新模型的缓存——结果「省钱操作」反倒让这一步的成本暴涨了近3 倍，还换来了一个更笨的模型。

这里有一个反直觉的结论：对长上下文Coding Agent来说，最便宜的模型未必能完成最便宜的任务。真正决定成本的，不只是模型单价，还有每次切换会浪费多少缓存。

真正有效的省钱架构，是让子智能体（Subagent）干那种「不继承主上下文」的脏活累活（比如去代码库里搜完 5 万 Token 的日志，只提炼 200 个字汇报给主智能体），从源头控制主上下文膨胀。

最后，对于大规模跑 Agent 的企业来说，开源自部署的大潮已经挡不住了。

正如 Diogo Almieda 指出的，如果企业天天用 API 跑海量 Agent，本质上是在把 KV 缓存带来的巨大成本红利拱手让给闭源厂商。

这也是为什么过去一年，大批科技巨头开始果断「逃离」闭源 API：Uber 靠架构优化把单 Token 成本砍了 50%，AT&T 降了 56%，Pinterest 更是狂降 90%；金融科技巨头 Revolut 干脆自购 56 块英伟达 B200 裸金属服务器自己跑。

还有越来越多团队通过 Modal、Fireworks、Baseten 这类专业推理云，跑起 DeepSeek 4.1 Flash、GLM 5.3、Kimi K3.1 Pro 等开源权重模型——唯有自己掌控推理栈，才能把 KV 缓存省下来的真金白银留在自己兜里。

好消息是，高昂的「缓存税」已经开始出现松动的裂痕。最近 Fable 5.1 刚刚把缓存读取价格从每百万 Token 1 美元直接腰斩再腰斩，砍到了 0.25 美元。

还没完。11月9日，Fable 5.2发布，缓存读取价格再次降至0.20美元。

短短两个多月，缓存读取价格比Fable 5时代便宜了整整80%。

更耐人寻味的是，Anthropic自己承认，仅仅降低缓存读取价格，就有望让复杂编程和Agent任务的整体使用成本下降最多约45%。

这说明对于疯狂调用工具、反复读取上下文的Coding Agent来说，缓存早已不是一项可有可无的优化，而是决定整笔账单的关键变量。

随着推理工程彻底从「黑盒魔术」变成软件工程师的必修常识，靠信息差赚暴利的红利期终究会慢慢收窄。
