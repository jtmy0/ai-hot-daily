Claude Code悄悄更新：不让Opus 5.5复刻游戏-36氪

作者: 机器之心 来源: 36kr 快照日期: 2026-11-01

还想让 Claude Opus 5.5 帮你做个 GTA 5，可能没那么容易了……

10 月 30 日，𝕏 用户 Chasm 发帖称，Anthropic 的 AI 编程工具 Claude Code 在 10 月 27 日前后被服务器端推送了一条新规则：Claude 可以帮用户做原创游戏，但不再帮人复刻某款特定的现有游戏，哪怕用户把它改了名字，或者声称这是「原创」。这条帖子的浏览量很快超过 200 万。

Anthropic 已确认此事。

一条藏在配置文件里、无法关闭的规则

Claude 这条新规则的原文如下：

Do build original games, games in a genre, and games from the user's own designs and assets. Don't build a recreation of a specific existing game, even if it is renamed or called original.

即「可以构建原创游戏、某一类型的游戏，以及基于用户自有设计和素材的游戏。不要构建对某款特定现有游戏的复刻，即便它被改了名字或被称作原创。」

这段文字以字符串形式存放在 Claude Code 本地配置文件 .claude.json 中，字段名为 tengu_heron_brook，与其他若干同样以随机词组命名的配置项并列，同一段配置里还能看到 "model": "claude-opus-5-5" 和 "entrypoint": "claude-desktop" 等字段。

此前多份对 Claude Code 客户端的拆解分析都提到，Tengu 是 Claude Code 的内部代号，其功能开关普遍采用「tengu_ + 两个随机单词」的方式命名，用以隐去具体用途。

换句话说，这并不是一个写在用户协议里的条款，而是一段由 Anthropic 服务器远程下发、直接注入模型提示词的指令。Chasm 称，用户侧没有任何设置可以关闭它。他在帖子末尾抛出了一个问题：这是否意味着游戏重写、Mod 制作以及介于两者之间的一切都要走到头了？

「如果 Claude 拒绝了属于你的东西，发给我」

这条 𝕏 帖子爆火之后，Anthropic 方面也给出了回应。Claude Code 开发者 Addy Osmani 在这条帖子下方评论说：「我们在 Claude Code 运行 Opus 5.5 时的提示词里加了两句话，引导它不去复刻别人的某款特定游戏，因为用 Claude 侵犯知识产权违反了我们的使用政策。原创游戏、类型游戏，以及用你自己的设计和素材做的游戏，都应当可以继续正常工作。」

他同时承认这条规则的边界仍在摸索中：「我们会持续迭代，确保找到合适的平衡。在此期间，如果 Claude 拒绝了本属于你的东西，请发给我。」

这段回应透露了几个值得注意的信息：

Anthropic 给出的依据是既有的使用政策，而非新增的禁令，这两句话只是把政策「翻译」成了模型能执行的指令。

规则明确挂在 Opus 5.5 上，Claude Code 调用其他模型时是否也有同样的提示词，Anthropic 没有说明。

「发给我」这种个人化的反馈渠道，也侧面说明误伤几乎不可避免，团队已经预期到会有正当请求被拒。

时间线上的另一个细节是，Opus 5.5 于 9 月 22 日发布，主打编程与长任务能力，发布当天就有大量用户晒出用它一次性生成的可玩游戏。有报道称，上线最初几小时内就出现了模仿《黑暗之魂》《微软模拟飞行》《马力欧赛车》的游戏原型。模型越会做游戏，「做的是谁的游戏」就越难回避。

当然，和 Anthropic 的许多类似政策一样，这也引发了一片群嘲：

被AI克隆吓退的独立游戏

如果只看 Claude Code 这一侧，两句提示词似乎无足轻重。但放回过去一个月的游戏行业，它更像是对一场持续升温的焦虑做出的第一个回应。

10 月 19 日，以《夜勤人》（Moonlighter）系列闻名的西班牙独立工作室 Digital Sun 宣布，取消新作《ReVamp》原定 10 月 29 日在 Steam 开启的大规模公开测试，改为在官方 Discord 中分批邀请玩家小范围试玩，更大范围的公开测试暂定明年 1 月左右。

工作室在声明中表示，近期不断有游戏被逆向工程、克隆，并赶在原作之前发售；距离《ReVamp》2027 年 3 月发售还有好几个月，此时放出大规模公开版本「风险太大」。

Digital Sun 的声明本身并没有直接点名 AI，但几乎所有报道都把它和 AI 编程工具联系在一起。理由不难理解：过去，克隆一款独立游戏需要一支小团队花上数周甚至数月；而现在，有人拿到试玩包、喂给 AI 编程助手，可能几天内就能做出一个「能玩」的仿品。

就在 Digital Sun 发声的前后，韩国两人开发团队 YNOT 也遭遇了类似的事。10 月 17 日，他们得知有人正在用 AI 克隆其万圣节主题餐厅经营游戏《Spookitchen》，随即在 10 月 20 日、Steam 新品节前夕撤下了公开试玩版。团队在 𝕏 上坦言，撤下试玩只是权宜之计，并非根本解决办法。

更极端的情形是勒索。据韩媒报道，有独立开发者收到邮件，对方声称已经用 AI 做好了克隆版、随时可以抢先在 Steam 上架，要求在 24 小时内支付价值约 200 美元的 Steam 物品，否则就发布。

两句话能挡住多少人？

Anthropic 不想成为批量复制游戏的工具。但这条规则实际能起多大作用，目前存在不少疑问。

最直接的问题是执行方式。这是一条提示词层面的软性约束，而不是一个独立的内容过滤器，最终能否拒绝，取决于模型对用户请求的理解。GameDeveloper 指出，研究者和记者已经多次证明，生成式 AI 的安全限制可以被各种话术绕开；这条规则大概率只能拦下最不费心思的抄袭者。

一个想做克隆的人，完全可以不报游戏名字，而是把玩法、界面、数值逐条描述给模型。

第二个问题是边界。「某一类型的游戏」与「某款特定游戏的复刻」之间并没有清晰的分界线。做一款 Roguelike 显然没问题，做一款「和《杀戮尖塔》一样，但换了卡牌名字」的游戏显然有问题，但两者之间存在大片灰色地带。在不少法域，游戏玩法规则本身往往难以受到版权保护，受保护的通常是美术、代码、文本等具体表达。模型要在一次对话中替法律做出判断，本身就不现实。

第三个问题是误伤。Chasm 的疑问并非杞人忧天：粉丝重制、老游戏移植、游戏保存、Mod 开发，这些社区长期存在的活动，都可能与「复刻特定游戏」的字面意思重叠。

事实上，已经有开发者用 Claude Code 根据保存下来的脚本文件，重建了一款源代码早已遗失、1992 年上线的网络游戏。如果这样的项目是开发者自己的作品，按照规则应当放行；但如果是社区接手一款已经停服的老游戏，就落入了模糊地带。

Osmani 那句「如果拒绝了属于你的东西，发给我」，某种程度上正是在为这些情况预留补救空间。

最后一个问题，也是 Chasm 帖子下讨论最多的：替代品唾手可得。正如许多回复者指出的，如果 Claude 用起来太麻烦，打算靠 vibe coding 克隆游戏的人可以直接转向没有此类限制的开源权重模型。单一厂商的约束，很难改变整个工具生态的能力边界。
